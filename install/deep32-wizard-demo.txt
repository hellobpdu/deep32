# deep32-wizard-demo.txt: the recorded deep32-setup runs that the wizard's --demo mode plays back.
#
# Both wizards (deep32-wizard.sh and deep32-wizard.ps1) start themselves in replay mode in place of
# deep32-setup, so the demo goes through the same process, pipes, events and screens as a real run. Nothing
# here touches the network, Docker, Tailscale or any disk outside the wizard's own log.
#
# Format: "=== NAME" starts a scenario. Other lines are printed as deep32-setup would print them, except:
#   .sleep SECONDS                        wait
#   .json {...}                           one event line (dropped when the replay runs without --events)
#   .ask ID QUESTION                      a question (an "ask" event, or "QUESTION [y/N] " in plain mode)
#   .prompt TEXT                          a hidden prompt read from the terminal (Connect's pairing code)
#   .dl FILE BYTES SECONDS [FROM [TO]]    download progress for FILE from FROM to TO per mille, over SECONDS
#   .if COND ... .endif                   COND: yes, no (the last answer), first, retry (the attempt),
#                                         digest, nodigest (--plan-digest given), windows, unix,
#                                         fixed (a fix pass of this demo already said yes)
#   .exit STATUS                          stop with this exit status
# {dir} is the download folder, {root} the Forge data folder, {py} the Python path, {tab} a tab.

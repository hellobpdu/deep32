ASK DEEP32

Ask runs on this workstation. The relay on the PC you pair it with (the
headend) runs Claude Code or Codex, which searches this workstation's RAG
through that relay. The relay picks the engine and offers the models and
strengths you can choose from.

Connect

The link comes up by itself whenever a wired port has a cable: d32-link takes
a DHCP address on that port and joins your tailnet, and Ask reaches the relay
on the paired PC at port 7452 over the tailnet. The first time only,
Tailscale needs its one-time login; after that every boot reconnects with no
input. In a Terminal:

  doas /usr/local/d32/sbin/d32-link status    the link, Tailscale and Ask
  doas /usr/local/d32/sbin/d32-link off       off until the next boot
  doas /usr/local/d32/sbin/d32-link on        on again now

More in /usr/local/share/doc/d32/LINK.txt.

Pair once

On the PC, install the relay, sign in to Claude Code or Codex there and open
the relay's pairing window, all with the relay's own steps.

On the workstation, switch to the text console (Ctrl+Alt+F1), log in as
your desktop user and run:

  doas /usr/local/d32/sbin/d32-chatctl pair work

Pairing changes what this workstation trusts, so the command runs only at
the text console, not in a Terminal window. Enter your login password for
doas. The pairing window on each side stays open for five minutes and allows
one connection attempt. When the relay connects, both screens show ten
words. Check that they are the same, type this workstation's words at the
relay's prompt, then type the relay's words here without the numbers and
press Enter. "PAIRED: pin stored; the link is active." means it worked.
After a failure nothing is trusted: open a new pairing window on both sides
and run the command again.

Ask's link to the relay is named "work"; this workstation has no other. A
link that already holds a relay's pin has to be unpaired before it pairs
again. Never give the pairing words or private keys to an assistant.

Use Ask

Open the Library subpanel of the front panel and select Ask Deep32, or type
/usr/local/d32/bin/d32-ask in a terminal. Ask in the Deep32 Library opens
the Ask window.

Type a question and press Return. The answer appears as it arrives. Ctrl+C
interrupts the current answer. Ctrl+D or /quit closes this conversation.

  /new              start a fresh session
  /status           show the link, the pairing, and the models and
                    strengths the relay offers
  /engine codex     label only: the relay on the paired PC picks the engine
  /ledger           show this session's RAG call names, outcomes, bytes and times
  /refs             list the last answer's numbered Library references
  /open             list those references again
  /open 2           open reference 2 in the Deep32 Encyclopedia
  /mods             show the question modifier key
  /history on       save questions and answers; off by default
  /help             show all commands

The relay on the paired PC picks the engine, Claude Code or Codex, and this
workstation can't change it: /engine and --engine only change the label in
the header, which shows "relay" unless you set one. The models and strengths
also come from the relay. In the Ask window, choose them from the Model and
Strength menus. In a terminal, /status lists them, and

  /usr/local/d32/bin/d32-ask --model MODEL --effort STRENGTH

uses that choice for every session it opens. Without a choice the relay
uses its default; a choice it doesn't offer is refused. If an interrupted
session cannot continue, use /new. History is off; /history on enables a
private history file on the workstation. Leave it off for material you
should not save.

Modifiers

Add a pipe followed by $letters to a question. Letters combine; /mods shows
the full key, grouped by search, length, scope and angle. Add +include,
-exclude, @doc, #release or %platform values after the letters. Double quotes
keep a phrase together. The status line shows the short summary.

  ospf nssa translator | $hv
  route maps | $c
  bgp bestpath | $nr #17.18 %iosxe-router

Ask expands these into instruction sentences for the headend. A Cisco pipe
without $ (show run | include ospf) stays in the question. Unknown letters,
stray tokens and an empty question show a local error before a session or
turn is sent. Modifiers apply to that question only. History, when enabled,
saves the question as typed.

References in answers

After an answer, the Library lists its references in first-seen order. Use
/open N with the number shown to open the document and its mapped section. A
section without an exact mapping opens the document and says 'section not
mapped'. Missing documents remain in the list as 'not in the Library'.
Install the matching Library pack and cite map to make them available.

Known compatible terminals also show clickable library: links. dtterm and
unrecognised terminals use the numbered list and /open N. A terminal must have
a library: handler configured before clicking can run the launcher; /open N
runs it directly. References use installed read-only maps and need no network.

Finish or unpair

Close Ask when finished. To revoke trust, log in as root at the text console
and run:

  /usr/local/d32/sbin/d32-chatctl unpair work

Also remove this workstation's pairing on the PC with the relay's own steps.
A changed relay certificate needs a deliberate unpair and a new pairing.

If it does not connect

Check the network link, d32-chatctl status at the root console, and the
relay's local status on the PC. A refused engine is configured and signed in
on the PC; the workstation never signs in to either model service. Do not
display or copy token files. The d32-edge-front off command also removes
Ask's local RAG listener. Ask needs that backend enabled, while the separate
d32front network service stays disabled.
